# onto-datamodel

A companion repo for a conference talk on grounding AI agents in your
data model: why an agent that can draft a data-model description isn't
the same as one you can trust, and what closes that gap.

This pipeline also generalizes into a broader internal Xebia toolkit,
not yet public.

## What this actually is

AI can clearly read SQL and draft what a data model means. The real
question is what has to be true before you'd trust that draft enough to
put it in front of a stakeholder, a dashboard, or another AI agent.

Using [jaffle_shop](https://github.com/dbt-labs/jaffle-shop) (a small,
well-known dbt + DuckDB demo project) as the working example, this repo:

1. Extracts structural facts straight from a dbt project's manifest — no
   LLM involved, zero cost, always correct by construction.
2. Has an agent draft an ontology entity for each model, citing exactly
   where every claim comes from.
3. Runs a validator that mechanically checks every citable claim and
   **flags — never silently trusts — the ones that genuinely require
   human judgment** (grain, relationship cardinality reasoning).
4. Catches real, unplanned mistakes this way, live — a paraphrased
   column description that silently dropped a unit, and a metric that
   cited a column the ontology hadn't actually documented yet.
5. Derives a few business metrics from the finished ontology, held to the
   same standard: every metric can only reference what's actually there.
6. Exports the validated ontology to real OWL (Turtle) and checks it
   against a set of SHACL shapes — the piece that makes it genuinely
   reusable outside this repo, in any RDF tool, not just here.

The pattern is copyable, not a black box, and it's honest about where AI
genuinely can't replace your judgment, which doesn't go away no matter
how good the tooling gets.

## Navigation

Start with `AGENTS.md`, the actual runbook (written for whichever AI
coding agent you're using: Claude Code, Codex, Cursor, or similar), if
you want to run this yourself. Otherwise, here's where everything lives:

| Looking for... | Go to |
|---|---|
| The dbt project (models, seeds, tests, macros) | `models/`, `seeds/`, `data-tests/`, `macros/`, `dbt_project.yml` |
| The generic pipeline (travels to your own dbt project) | `scripts/extract_structural_facts.py`, `scripts/schema.py`, `scripts/validate_grounding.py`, `scripts/review_signoffs.py` |
| The project-specific part (one file per entity/metric) | `scripts/generate_*_entity.py`, `scripts/generate_remaining_entities.py`, `scripts/generate_metrics.py` |
| Turning an unanswerable claim into a routed question | `scripts/generate_questionnaire.py`, `questionnaire_routing.json` (the *rendered* questionnaires are gitignored, they carry real answers once filled in) |
| Standards export (OWL/Turtle + SHACL validation) | `scripts/generate_owl.py`, `shapes.ttl`, `scripts/validate_shacl.py` |
| Tests, including negative controls | `scripts/test_*.py` |
| Generated artifacts (all gitignored, rebuilt from the above) | `target/manifest.json` (`dbt build`), `structural_facts.json` (`extract_structural_facts.py`), `ontology.ttl` (`generate_owl.py`), `ontology_report.html` (`render_ontology.py`) |
| Why the pipeline is built this way, not just what it does | `docs/adr/` |
| Signed-off review history | `AUTHORIZED_SIGNERS.md`, `review_signoffs.json` (untracked until someone signs something) |

## Quick start

```bash
uv sync --group dev
uv run dbt build                                  # produces target/manifest.json
uv run python3 scripts/extract_structural_facts.py
uv run python3 scripts/validate_grounding.py
uv run pytest -v
```

See `AGENTS.md` for the full walkthrough, including how to ground a new
model end to end.

and an undocumented hardcoded column with a sloppy inline comment (see
`models/staging/stg_supplies.sql` and
`models/staging/_staging_models.yml`), all fictional, none of it present
in dbt Labs' original jaffle_shop.

## Status

10/10 jaffle_shop models grounded, 3 business metrics derived and
validated against the ontology itself, a human-signoff gate for every
claim that can't be mechanically checked, and a full export to OWL
validated against SHACL shapes (`ontology.ttl`, 654 triples, 10 classes,
0 SHACL violations). The bespoke citation-grounding validator
(`scripts/validate_grounding.py`) is still the source of truth for
whether a claim is actually true against the dbt manifest, SHACL checks
the exported graph's structure, it can't check that.

This has been proven on a small, deliberately clean project plus one
deliberately messy table, not yet at the scale of a real production
system. Treat it as a working discipline, still being stress-tested, not
a finished tool.
